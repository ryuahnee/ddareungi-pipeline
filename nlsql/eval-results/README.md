## 공통 실패와 해석

- 세 모델 모두에서 실패한 문항은 없다. gpt-5.5와 gpt-6.1-sol은 `agg01`, `weather02`, `subway03`에서 함께 실패했다. 생성 SQL을 확인하면 수집 시각이나 관측 행 수 등 요청하지 않은 보조 컬럼을 추가해 정답과 컬럼 수가 달랐다. 값 계산 오류로 단정할 수 없으며, 이번 규칙은 요청한 결과 형태까지 엄격하게 비교한다.
- gpt-6.1-sol의 추가 실패 `agg02`, `agg04`도 같은 형태의 보조 컬럼 추가였다. 75개 생성 SQL 모두 검증·실행에 성공했으며 API 실패·검증 거부·SQL 오류는 없었다.
- 원인 추정: 결측·관측 범위를 설명하라는 공통 프롬프트를 일부 모델이 설명문 대신 SELECT 보조 컬럼으로 반영한 것으로 보인다. 비교 후 프롬프트나 정답을 조정해 재평가하지 않았다.

## 비교 규칙과 한계

- 숫자 타입만 소수 둘째 자리 HALF_UP으로 반올림하고 컬럼명은 무시한다. 기본적으로 행 집합을 비교하며, 정답의 최상위 ORDER BY와 LIMIT/FETCH가 함께 있으면 순서도 비교한다. NULL과 문자열 NULL, 숫자형 문자열과 숫자는 구별한다. 잘린 결과는 통과시키지 않는다.
- 문항마다 정답과 생성 SQL을 동일 REPEATABLE READ 트랜잭션에서 실행한다. 실시간 mart는 문항·모델 실행 사이에 갱신될 수 있다. 각 보고서에 실행 시각, 코드 커밋, 평가셋·스키마·용어 사전 해시와 결과 해시를 기록했다.
- 날짜 조건은 고정 KST 날짜(2026-10-19, 2026-10-21, 2026-11-08)로 작성했다. 스냅샷과 최신 날씨 mart는 과거 이력을 보존하지 않으므로 추후 데이터 교체 뒤 해당 문항은 비어 있을 수 있다. 정답 검증 단계에서 빈 결과/100행 초과는 거부한다.
- 25개 명시적인 질문·단일 실행의 결과로, 일반적인 자연어 질문 전체에 대한 모델 우열이나 안정성을 의미하지 않는다. 지연에는 요청 왕복·응답 해석이 포함되고 DB 실행·로그 저장 시간은 포함하지 않는다. 토큰은 usage의 prompt와 completion 합계이며 비용이 아니다.

## 재실행

```bash
./gradlew :nlsql:run --args='--eval --model gpt-5.4-mini-2026-03-17'
./gradlew :nlsql:run --args='--eval --model gpt-5.5-2026-04-23'
./gradlew :nlsql:run --args='--eval --model gpt-6.1-sol'
```

환경변수는 git 제외 env의 KEY=VALUE를 줄 단위로 읽어 프로세스 환경에 설정한다. 셸 source로 해석하지 않는다. 원문 비밀값·연결 주소·결과 행은 이 보고서와 질문 로그에 기록하지 않는다.
