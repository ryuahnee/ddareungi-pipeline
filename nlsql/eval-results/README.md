## 회귀 하락 원인

- strict 52%(13/25): 11문항은 전체 대상 수 등 보조 컬럼을 추가해 결과 형태가 달라졌지만 relaxed에서 요청한 값이 일치했다. 개수 답장에 전체 수를 함께 조회하도록 한 의도적인 SELECT 형태 변경의 영향이다.
- relaxed 96%(24/25): `scd03`만 실패했다. 정답은 SCD 버전 행 수 `COUNT(*)`인데 생성 SQL은 주소별 고유값 수 `COUNT(DISTINCT addr1)`를 버전 수로 해석했다. 실제 데이터에서 4개 대여소의 두 집계가 다름을 확인했다. 주소는 버전의 고유 식별자가 아니므로 버전 수와 같다고 볼 수 없다.
- 새 프롬프트의 영향과 단일 실행의 생성 변동을 분리할 수 없어 인과를 단정하지 않는다. 향후 용어 사전에 버전 1행의 의미를 더 명확히 할 수 있으나, 이번 평가 후 프롬프트/정답을 바꾸거나 유리한 결과로 재평가하지 않았다. 이 회귀 결과를 그대로 보관한다.

## 비교 규칙과 한계

- strict는 기존 규칙을 유지한다. 컬럼 수·위치가 일치해야 하며 이름만 무시한다. 숫자 타입은 HALF_UP 소수 둘째 자리, 기본 비교는 행 집합, 정답 최상위 ORDER BY+LIMIT/FETCH 문항은 행 순서도 비교한다. NULL과 문자열 NULL, 숫자형 문자열과 숫자는 구별하고 잘린 결과는 통과시키지 않는다.
- relaxed는 정답 컬럼을 생성 결과의 서로 다른 컬럼에 일대일 대응시켜 생성 결과를 투영한 뒤 동일한 전체 행 비교를 수행한다. 보조 컬럼·컬럼 순서는 허용하지만 값 변경·같은 컬럼 재사용·행 사이의 컬럼 관계 뒤섞임은 허용하지 않는다. strict 불일치·relaxed 일치는 추가/재배치 컬럼을 제외한 요청 결과가 같다는 뜻이다.
- 최신 run만 보관하는 mart_station_snapshot, mart_weather_depletion, mart_depletion_with_weather 문항은 날짜 조건 없이 현재 스냅샷을 조회한다. 관련 조인은 station_id와 run_id로 최신 run을 맞춘다. 다른 이력 문항은 고정 KST 날짜를 유지한다.
- 예시와 겹치던 top01은 평균 주차 자전거 수, subway01은 18시대 주변 대여소 수, transition01은 07→09시 평균 거치율 하락폭으로 바꿨다.
- 문항마다 정답과 생성 SQL을 동일 REPEATABLE READ 트랜잭션에서 비교한다. 문항·모델 사이에는 실시간 갱신이 있을 수 있으며, 각 보고서의 코드 커밋·실행 시각·평가셋/스키마/사전/결과 해시로 추적한다. 결과 행 자체는 보관하지 않는다.
- 25개 명시적 질문·단일 실행의 결과다. 모델 전반의 우열이나 안정성을 의미하지 않는다. LLM 지연은 요청 왕복·해석 시간이고 DB·로그 저장은 제외한다. 토큰은 prompt+completion usage이며 비용이 아니다.

## 재실행

```bash
./gradlew :nlsql:run --args='--eval --model gpt-5.4-mini-2026-03-17'
./gradlew :nlsql:run --args='--eval --model gpt-5.5-2026-04-23'
./gradlew :nlsql:run --args='--eval --model gpt-6.1-sol'
```

환경변수는 git 제외 env의 KEY=VALUE를 줄 단위로 읽어 프로세스 환경에 설정한다. 셸 source로 해석하지 않는다. 원문 비밀값·연결 주소·결과 행은 보고서와 질문 로그에 기록하지 않는다.
